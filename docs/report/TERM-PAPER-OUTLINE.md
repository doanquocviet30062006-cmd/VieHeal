# Term paper outline

Target body: approximately 50 pages, excluding optional appendices as institutional rules allow.

1. Front matter: cover, declaration/acknowledgment if required, abstract, contents, lists of figures/tables/abbreviations.
2. Introduction and problem (5 pages): clinic context, problem statement, users, research method, validated findings, objectives, scope and contribution.
3. Requirements analysis (5 pages): actors/journeys, functional/non-functional requirements, acceptance and traceability.
4. System architecture (7 pages): AS-IS evidence, target modular monolith, domain model, workflows, decisions and quality attributes.
5. Android and UI/UX (11 pages): module graph, UDF/state/lifecycle, navigation, networking/auth, Room/offline, security, design system, Figma and accessibility.
6. Backend/database/security (7 pages): API, authorization, V1–V24 model, enforcement boundary, error handling and security debt.
7. AI integration (7 pages): use case, gateway, prompt/context/schema, safety, 15-case evaluation and limitations.
8. Testing and evaluation (5 pages): pyramid, backend results, Android state tests, AI results, usability/performance evidence.
9. Results, limitations and roadmap (3 pages): verified achievements, gaps, production hardening and future modules.
10. References and appendices: API detail, test tables, survey instrument, evidence manifest as appropriate.

Write past tense only for verified executed work. Target designs use future/conditional language. Each result cites source, test report, figure or appendix.
